6	Deploy	Only deploy if everything above passed. Clean code, clean image.

This is called a Dynamic Multi-Language Pipeline.
The Idea

One Jenkinsfile → detects the project type → runs the right steps

If requirements.txt found  → Python flow
If package.json found      → Node flow
If pom.xml found           → Java flow

How it works
groovy

pipeline {
    agent any

        IMAGE_NAME = "my-app"
        IMAGE_TAG  = "latest"

Yes, great thinking. This is a cleaner architecture. The idea is:

Pipeline only orchestrates. All logic lives outside.
The Architecture

repo/
├── Jenkinsfile                  ← only stages, no logic
├── pipeline-config.yml          ← all project config lives here
└── scripts/
    ├── detect.sh                ← detects language
    ├── install.sh               ← installs dependencies
    ├── test.sh                  ← runs correct unit test
    └── deploy.sh                ← handles deploy logic

How it works

Jenkinsfile reads config → calls scripts → scripts do the work

Jenkinsfile becomes just:
groovy

stage('Unit Test') {
    steps {
        sh './scripts/test.sh'
    }
}

No language logic inside pipeline at all.

image_name: simple-python-app
image_tag: latest
app_port: 5000
sonar_project_key: simple-python-app

network: jenkins1

Step 2 — scripts/detect.sh
bash

mkdir -p scripts

cat > scripts/detect.sh << 'EOF'
#!/bin/bash
APP_DIR=$(grep 'app_dir' pipeline-config.yml | awk '{print $2}')

if [ -f "${APP_DIR}/requirements.txt" ]; then
    echo "python"
elif [ -f "${APP_DIR}/package.json" ]; then
    echo "node"
elif [ -f "${APP_DIR}/pom.xml" ]; then
    echo "java"
else
    echo "unknown"
    exit 1
fi
EOF

#!/bin/bash
set -e

echo "Installing dependencies for: ${LANG_TYPE}"

  python)
    pip3 install -r ${APP_DIR}/requirements.txt --break-system-packages
    ;;
  node)

    ;;

esac
